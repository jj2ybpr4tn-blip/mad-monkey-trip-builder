# For Charlie: the trip builder changes for the ALL IN backend

Four commits on top of `CFSiteDesign/mm-squad-trips` (`ced803c`, "Trip builder: Ewan's WhatsApp, plus a test send to Ewan"). They apply cleanly in order and rebuild the tree exactly.

```bash
git checkout -b trip-builder-update
git am --3way /path/to/handoff/all-in-backend/000*.patch        # the four .patch files, in order
```

| # | What it does |
| --- | --- |
| **0001** | **The new-trip email and the crew review page.** The email Ewan gets now shows the whole trip (stops, tours, travel, money, heads-up) with Approve / Not approved / Edit it buttons. They open a review page in the builder. Opening a link only reads; nothing is sent, charged or refunded until a person confirms. [docs/trip-builder-crew-review.md](docs/trip-builder-crew-review.md) |
| **0002** | **Pay the rest your way.** After the crew approves, the deposit already paid counts and the guest chooses: pay it all now, be charged a week before they leave (the card saved with the deposit), or instalments when they leave 60+ days out. Daily job takes the payments and sends reminders. [docs/trip-builder-payments.md](docs/trip-builder-payments.md) |
| **0003** | **The builder itself.** Phone fixes (stop cards, home page, map), buttons that did nothing, a quiz that no longer drops must-dos silently, shorter pages, the pay-your-way screens. Generated by `scripts/sync-allin.mjs` from the builder source, so `public/trip-builder` stays in step with it. |
| **0004** | **Edit your trip any way you like, and chat to an AI to change it.** After the quiz a traveller can remove, add, swap, reorder, re-time and undo anything on the screen (front end only: ships with the site). On top of that, a chat panel where they say what they want and the AI makes the edits (needs the `trip-builder-chat` Edge Function, a usage-counter migration and an Anthropic API key; until the key is set the builder uses a built-in quick helper, so shipping this patch breaks nothing). [docs/trip-builder-chat.md](docs/trip-builder-chat.md) |

## To ship it

1. **Migration** `supabase/migrations/20261020120000_trip_builder_payments.sql`: five nullable columns on `trip_builder_requests`, and a daily cron job (03:00 UTC, same shape as the others: `x-cron-secret` from `get_cron_secret()`).
2. **Deploy these functions:** `trip-builder-request`, `trip-builder-status`, `trip-builder-admin`, `trip-builder-test-emails`, `stripe-webhook`, and the new `trip-builder-pay` and `charge-trip-builder-payments` (the `_shared` files go with them). `supabase/config.toml` already lists the new two.
3. **Deploy the site** (the admin tab has a "Review page" button and shows payment plans; `public/trip-builder` has the new builder).
4. Optional secret `TRIP_BUILDER_TEAM_EMAILS` (comma separated) to copy the team on every new-trip email. No new secret is needed otherwise: links are signed with `ADMIN_PASSWORD` (`TRIP_BUILDER_LINK_SECRET` overrides it).
5. Press the **test send** (`trip-builder-test-emails`): it emails Ewan every trip builder email and creates a sample request `MM-SAMPLE` so the buttons work. Approve the sample, then open the "choose how to pay" email to see the guest side. Don't pay the sample's links.

**For 0004 (the AI chat), on top of the above:**

6. **Migration** `supabase/migrations/20261022090000_trip_builder_chat_usage.sql` (a small counter table and one function; it keeps daily use per person and overall so cost can't run away).
7. **Secret `ANTHROPIC_API_KEY`**, then deploy `trip-builder-chat`. **Whoever owns that key pays the bill** (roughly 5 to 15 cents a chat message on the default Opus 5.5; `TRIP_CHAT_MODEL=claude-sonnet-5-5` halves that; daily limits are built in). Settings and costs are in [docs/trip-builder-chat.md](docs/trip-builder-chat.md). Not tested against the real Claude API, only a fake one: try a few messages before telling anyone.

Things worth knowing:

- **Trips already waiting** when this goes live have no saved card (the deposit checkout didn't save one), so their guests can only choose "pay it all now". New trips can choose all three.
- Approving no longer makes a Stripe link (those expire in 24 hours, so a link in an email opened the next day was dead). The Checkout page is made when the guest presses the button.
- The card is charged off-session with an idempotency key per payment, so a double run can't charge twice. A declined card is retried 2 days later, up to 4 times; the guest gets an email with a way to pay by hand and Ewan is told.

Not tested against live Stripe, Resend, the Supabase gateway or the real Claude API: please run the test send and one small real payment first.

## Keeping the copy in step

`public/trip-builder` is the trip builder plus its own `config.js`. When the builder changes, from the builder repo: `node scripts/sync-allin.mjs /path/to/mm-squad-trips` (add `--check` to see what would change). It copies the shared files, drops the SEO footer, and only ever adds config keys, never changes yours.
